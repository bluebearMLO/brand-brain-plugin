# System file template → `04-the-<slug>-system.md` ("read first")

This file defines what the product actually is. Every other file sits on top of it, so write it first and keep it short and factual. If the sources leave the definition unclear (who makes which part, what is in-house vs bought in, what the brand really sells), stop and ask the owner. Don't pick one.

Typical mistakes this file exists to prevent:
- treating an in-house capability (own factory, own frame, own software) as a bought-in part or a cost line;
- treating a partner's product as swappable ("or equivalent") when the brand is built on it;
- treating a sister company or team as a separate supplier with transfer prices;
- describing the product by what it is called on a superseded website rather than by the current plan.
